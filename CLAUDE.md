# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sky is a SwiftUI iOS app (iOS 26 deployment target, iPhone only) for capturing and browsing sky gradients. Pure SwiftUI, no external dependencies, no test targets. Saved skies persist as one JSON file in Application Support (`SkyStore`), seeded on first launch with the five Figma palettes. The UI is implemented from a Figma design — color stops and layout metrics in the code are taken verbatim from the Figma fills. DECIDED: skies blend in Oklab (`Oklab` in `SkyGradient.swift`; the card draws 16 Oklab samples per span and `SkyStop.mix` uses the same math, so adding a stop never changes the sky). Figma can only blend in sRGB, so Figma is the source of truth for stop colors and locations, not for how the gradient looks between them — the in-between midtones are deliberately a little lighter and less gray than Figma's preview. Don't bake samples into the Figma fills.

## Build & Run

There is one Xcode scheme, `Sky`. Build from the command line with:

```sh
xcodebuild -project Sky.xcodeproj -scheme Sky -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

`scripts/dev.sh` is the Xcode Run button, headless: it builds, installs, and relaunches the app on the connected iPhone (`--sim` for the simulator), then rebuilds on every Swift file save (`--once` to skip watching).

Uses iOS 26 APIs (`.glass` button style / Liquid Glass, `scrollEdgeEffectStyle`, `safeAreaBar`), so building requires a recent Xcode with the iOS 26 SDK.

## Prototyping workflow

Interactions are prototyped in `prototypes/*.html` before being built in Swift: a single self-contained HTML file with the phone mock (402×874, geometry copied verbatim from the app/Figma) plus a side panel of tuning sliders (spring duration/bounce, thresholds, toggles) so the feel can be iterated live. Once an interaction feels right, port it to SwiftUI using the tuned values. New prototypes default their springs to the app's existing vocabulary in `Sky/Animations.swift` (quick, subtle: ~0.2–0.4s, bounce 0–0.2); once values ship there, sync the prototype defaults back to them. Serve with `python3 -m http.server` in `prototypes/` (the Chrome extension can't open `file://`).

- `stop-picker.html` — drag a stop tag vertically to move its gradient location (zoom-in scene, hex→% label morph).
- `color-edit.html` — tap a tag: card springs to full width (Figma 152:2332), tapped tag docks at the right edge, and a glass "Choose color" sheet (Figma 153:227) rises with hue/saturation/brightness sliders + scrubbable value pills (HSB, not HSL — chosen so values cross-check 1:1 with Figma's own color picker; the brightness track runs black→color, no white end). The card's aspect ratio is deliberate and NEVER changes; when a low stop would hide behind the sheet, the whole scene rides up (`--shift-y`) just enough to clear it, following the stop as it moves. In edit mode, dragging a tag moves its stop (label reads out %); tapping opens the sheet. DECIDED: while the sheet is up the docked tail is a SILENT drag handle — vertical drag moves the stop with no label/% readout (haptic ticks only), the card's ride-up follows live, and taps on it do nothing. (Prototype's tail mode shows a guide line + % bubble; the app deliberately drops that text.) The card travel reuses `Animation.editSlide` (0.22s/0). Ported as `ChooseColorSheet` (native sheet: detent/grabber/glass/swipe from the system) + tap-vs-grab split in `StopTagColumn` + `colorEditShift` in both overlays.
- `bottom-bar.html` — adding and removing colors in stops mode. A glass "+" (bottom trailing, where the gallery's plus lives) adds a color Figma-style: midpoint of the biggest gap, interpolated color, tag slides in from the right and fades in (chosen: 80pt, 330ms, no bounce, landing haptic, no neighbor reaction — the panel still offers the rejected reactions for comparison). Pulling a tag to the right, away from the card, past a threshold detaches it and it flies off the edge, removing the stop. Panel picks a 2/3/6-color example gradient. Ported: `[SkyStop].addingStop()` / `.fading(_:by:)`, `TagPull` + the birth zone in `StopTagColumn` (touch the empty space beside the card → a tag docks at that height; dismiss = the delete pull), `addStop()` in the overlays; the working "+" sits in the gallery plus's spot. `#edit+add2` in the URL deep-links to stops mode with two inserts, for screenshots.
- `gallery-controls.html` — jiggle mode on the gallery grid (the home-screen idiom, in Liquid Glass). Hold a tile or the empty background: every tile starts to wobble (restrained: ~1°, 300ms, each on its own beat), a small glass "−" badge pops onto each, and the bottom-right "+" morphs into a "✓". Tap a badge to delete (tile shrinks away, grid closes up); drag a tile to reorder (others make room). Once anything changed, a glass "↺" appears bottom-left and puts the grid back the way it was; "✓" or a background tap commits and settles. No Done pill, no toast. Panel tunes hold time, wobble presets/angle/period/bob/sway, badge glyph/position/size/pop, the +→✓ morph, when ↺ shows and how much it undoes, delete guard (↺ vs. tap-again red badge), exit style, pick-up lift and reflow springs. A move before the hold lands cancels it (that's the scroll). `#jiggle` in the URL starts awake. Ported: `Jiggle` constants + `Wobble` + `DeleteBadge` in `Components/JiggleMode.swift`, the +→✓ crossfade as `alternateSystemName` on `GlassIconButton`, and the mode itself (working-copy `draft`, ↺ = back to `store.items`, slot-offset drag reorder, `SkyStore.replaceAll` on ✓) in `GalleryView`. `SKY_AUTOPLAY_JIGGLE=1` wakes the grid on launch. DECIDED: the badge is a flat translucent disc (semantic background fill, quaternary rim, tertiary glyph) riding the wobble — not Liquid Glass. Glass that wobbles breathes in size (tried plain, pinned, and in a GlassEffectContainer) and materials make the grid lag; the flat disc holds its size. The wobble is a frame clock (`TimelineView`), not `repeatForever` — a repeating animation leaked rotation onto tiles after exit. Keep backdrop effects and blurred shadows off the idle tiles or the grid lags.
- `color-picker.html` — rethinking the Choose-color sheet. Starts on the blank sky (white → gray), where HSB's hue slider is a DEAD control (saturation 0 → every hue is the same gray). Panel compares: model HSB (Figma's axes) vs. OKLCH (lightness · chroma-as-%-of-sRGB-max · hue, the same space the sky blends in; hue turns without changing lightness); "wake" (the first hue move on a gray lifts saturation/chroma to a tunable amount and pulls pure white/black in, thumbs glide there; the OKLCH hue track previews where you'll land); three sliders vs. a 2D pad + hue; header A (today: 24pt leading title, flat X) / B (iOS 26: small centered title, glass X trailing) / C (X = revert, ✓ = keep) / D (X only) / E (default, the UIColorPickerViewController layout: EYEDROPPER leading, small centered title, glass X trailing), title size. The dropper glyph in the app is the SF Symbol `eyedropper.full`, in the ✕'s exact treatment (19pt black rounded, tertiary) — tried the design's own SVG as a Path (came out lighter than the ✕ in the glass sheet: iOS inks shapes and images differently) and as a template image; the system symbol matches by construction. Tapping it drops the sheet and OUR OWN SKY ZOOMS IN to fill the screen — DECIDED: no photos, the eyedropper picks from the gradient preview itself. A full-screen copy of the card's gradient (drawn row by row in Oklab) starts exactly over the card (clipped to its rect/corner, content squeezed to 370/402 × 548.66/874, ride-up included) and opens to the whole phone; after the pick it zooms back into the card showing the updated sky. It's the hero move, so it reuses those springs: in = `heroOpen` (0.31s, bounce 0.19), out = `heroClose` (0.26s, 0). LAYERS are fixed for every state so nothing pops across anything mid-move: card < zoomed sky + lens < HEADER < sheet — the header rides above the sky so the title holds its place through the whole pass (it used to be covered and reappear late, as if waiting on the sheet); and the card doesn't move while picking (ride-up kept), so the zoom leaves from and lands on the card exactly and no edge slides out from under it. The lens FLIES OUT OF THE PIPETTE BUTTON (its frame comes from the sheet via `onPick(CGRect)`): button-sized (44/120) at the button → full size mid-sky on the zoom's own `heroOpen`, no delay, one motion with the zoom; on pick/cancel it flies back into the button on `heroClose`, fading, carrying the color. NO invented springs, no materialize (tried: read slow, not ours). Glass covers the WHOLE lens (`.glassEffect(.clear, in: .circle)` over the magnified sky) — a rim-only ring was tried and rejected: it changed the look. The loupe is a Liquid Glass lens (for the app: `glassEffect`), not a pixel grid: smooth 3× magnification, bright rim + top-left specular, the sampled point marked by the sheet's own slider thumb (`ColorThumb`, 36pt/3pt ring, filled with the color you'll get) — no invented reticle. DECIDED: the lens JUMPS TO THE FINGER ON TOUCH-DOWN and follows the drag from there (tried relative trackpad-style dragging first; rejected); lift after a drag takes the color under the lens. No explainer text. CANCEL IS THE HEADER'S TRAILING BUTTON: in create, the ✓ swaps to ✕ (`GlassIconButton` alternateSystemName, `glyphMorph`) and the leading ✕ fades out (one ✕ on screen); in detail, a ✕ pops in at that trailing spot and the ‹ fades out. `#pick` opens the sheet, then plays the zoom. DECIDED for the app: HSB stays (Figma cross-check), wake on (to 100% saturation, black to 50% brightness, gray = below 1%), three sliders, header E with a small centered title (22pt BOLD rounded, the app's title weight — semibold read thin; tried 24 and 17). Ported: `wakingHue` + the eyedropper/title/✕ toolbar in `ChooseColorSheet` (flat quaternary buttons, as the ✕ already was), `PipetteGlyph` + `EyedropperSession` + `SkyEyedropper` (zoom layer = the card itself, `GradientCard` with its 55pt shape, hidden between passes, its FRAME animated — tried a render-only scale + separate animatable clip: under a fast trigger the two fell out of step and showed square corners; lens = its own view `EyedropperLens` owning the drag, so a drag re-renders only the lens; the magnified sky is a lens-sized strip of the gradient (3× tall, offset to the sampled point — it only varies vertically), never a full-screen layer scaled + masked + shadowed per frame; gradient built once per pass; `.glassEffect(.clear)` on top) in `Components/Eyedropper.swift`, `[SkyStop].hex(at:)` for the read, and `startPick`/`finishPick` in both overlays. DECIDED (after trying the alternatives): the SHEET DROPS for the pass (swallowed onDismiss so the card stays put) and rises again with the new color — collapsing it to a tiny detent instead was tried and REJECTED: the floating sheet turns into a rectangle as it shrinks. A dropped sheet leaves something behind that eats the NEXT TOUCH (the lens missed the first drag every time, however long you waited), so the lens is driven by a recognizer on the WINDOW (`WindowTouches`: long-press, 0s, simultaneous with everything, never cancelling), not a SwiftUI gesture; touches starting on the header's ✕ are excluded so it cancels; the sky zooms UNDER it to the WHOLE SCREEN, with the GRADIENT scoped to the safe area (full width, top inset → bottom inset) and its first/last colors running on past it to the screen edges — a safe-area-sized rounded sky let a ridden-up card peek out around it; frame, gradient scope and 55pt corner are one layout on one spring, and at full screen the corner hides inside the display's rounding — keeping the sheet up made its glass re-blur the moving sky every frame (laggy) and left the sheet in view; a separate overlay window made the zoom flaky. The docked tag is GONE the instant a pass starts (no fade) and comes back IN STEP WITH the zoom home — as a twin drawn ON TOP of the sky, glued to its trailing edge, fading in on `heroClose`, handed over to the real tag (hidden until then: `EyedropperSession.hidesTag` → `StopTagColumn.hidesDocked`) on the spot where the sky lands. Fading the real tag in beneath the sky made it pop out when the edge passed. The lens is clamped to the zoomed sky and reads location relative to it. A drag's release takes the color under the lens; a quick TAP takes the color right where it landed and goes back too (under 4pt of travel counts as a tap). Closing the gradient dismisses the sheet (and any pass) at once, so it leaves with the card (`isClosing` swallows its onDismiss). Wake defaults as tuned: on, wake to 100%, gray below 1%, no dimming. - `app-icon.html` — the app icon as an AIRPLANE WINDOW: a panel with a rounded opening cut in it, a well running inward, and the sky at the bottom of it. One thing, no card/tags/label, has to survive at 29pt. Canvas-drawn so the 1024 export is exactly the preview; every metric is a share of the icon size, and the board renders the same drawing at all seven iOS sizes (180→29, actual pixels), at 52pt on light and dark home screens, and once per palette. SHAPE: the real Apple squircle — each corner an arc with Bézier segments easing into both edges (Figma's squircle construction), the mask being 22.37% radius at 60% smoothing (`MASK_R`/`APPLE_SMOOTHING`), built as an SVG path string handed to `Path2D` so the arc stays exact. `layout()` derives three shapes: mask, aperture (concentric with the icon corner, then opened toward a full round by `roundness` — an aircraft window is nearly all corner), and glass. THE WELL (`drawWell`): DECIDED against four mitred faces — they read angular and cheap. Instead the wall is shaded by which way it faces: at perimeter angle φ the inward normal is (−cos φ, −sin φ), so the light it catches is cos(φ − θ), which is a CONIC GRADIENT about the centre (`wallLight`). That makes the corners round and the shading seamless. Depth comes from 22 concentric rings stepping aperture→glass (`lerpBox`), each dimmer and more occluded than the last; below ~16 rings the alpha steps show as machining contours. Real parallax: the glass is offset along the light, so one side of the tunnel is visibly wider — that off-axis view is what makes a recess read as a recess rather than as a drop shadow. Plug mode flips the lighting for a face standing proud. Panel gives control of all of it: panel width, wall thickness, opening roundness, light angle, look off-axis, wall shading, edge highlight; plus material (flat/plastic/brushed/paper/leather/glass = light-shaping gradient + a generated grain tile composited in `overlay`, tile sized as a share of the icon so texture scales and vanishes below ~3px like real texture), panel tint, vignette, gradient angle/zoom, and an Apple template grid over the hero (dotted eighths, three circles, diagonals — preview only, never exported). Default panel width 7% puts the opening on the grid's first ring. DECIDED: the iOS 6 gloss shine is OFF by default (slider kept at 0) — it fights the material. Material lighting and grain go over the WHOLE icon after the sky, so it reads as one surface catching one light. GOTCHA: shapes are `Path2D` values, never drawn straight onto the context — `innerShadow` composes a rect with the shape as an even-odd hole, and a builder that called `ctx.beginPath()` wiped the rect and filled every swatch solid black. "Download 1024 PNG" writes the square unmasked master for `AppIcon.appiconset`. Deep links combine with `+`: `#leather+plug+dusk`, `#metal+glazed+ember`, `#bleed`, `#grid`.

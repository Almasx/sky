# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sky is a SwiftUI iOS app (iOS 26 deployment target, iPhone only) for capturing and browsing sky gradients. Pure SwiftUI, no external dependencies, no test targets. Saved skies persist as one JSON file in Application Support (`SkyStore`), seeded on first launch with the five Figma palettes. The UI is implemented from a Figma design — color stops and layout metrics in the code are taken verbatim from the Figma fills. DECIDED: skies blend in Oklab (`Oklab` in `SkyGradient.swift`; the card draws 16 Oklab samples per span and `SkyStop.mix` uses the same math, so adding a stop never changes the sky). Figma can only blend in sRGB, so Figma is the source of truth for stop colors and locations, not for how the gradient looks between them — the in-between midtones are deliberately a little lighter and less gray than Figma's preview. Don't bake samples into the Figma fills.

## Build & Run

There is one Xcode scheme, `Sky`. Build from the command line with:

```sh
xcodebuild -project Sky.xcodeproj -scheme Sky -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

`scripts/dev.sh` is the Xcode Run button, headless: it builds, installs, and relaunches the app on the connected iPhone (`--sim` for the simulator), then rebuilds on every Swift file save (`--once` to skip watching).

Uses iOS 26 APIs (`.glass` button style / Liquid Glass, `scrollEdgeEffectStyle`, `safeAreaBar`), so building requires a recent Xcode with the iOS 26 SDK.

## Prototyping workflow

Interactions are prototyped in `prototypes/*.html` before being built in Swift: a single self-contained HTML file with the phone mock (402×874, geometry copied verbatim from the app/Figma) plus a side panel of tuning sliders (spring duration/bounce, thresholds, toggles) so the feel can be iterated live. Once an interaction feels right, port it to SwiftUI using the tuned values. New prototypes default their springs to the app's existing vocabulary in `Sky/Animations.swift` (quick, subtle: ~0.2–0.4s, bounce 0–0.2); once values ship there, sync the prototype defaults back to them. Serve with `python3 -m http.server` in `prototypes/` (the Chrome extension can't open `file://`).

- `stop-picker.html` — drag a stop tag vertically to move its gradient location (zoom-in scene, hex→% label morph).
- `color-edit.html` — tap a tag: card springs to full width (Figma 152:2332), tapped tag docks at the right edge, and a glass "Choose color" sheet (Figma 153:227) rises with hue/saturation/brightness sliders + scrubbable value pills (HSB, not HSL — chosen so values cross-check 1:1 with Figma's own color picker; the brightness track runs black→color, no white end). The card's aspect ratio is deliberate and NEVER changes; when a low stop would hide behind the sheet, the whole scene rides up (`--shift-y`) just enough to clear it, following the stop as it moves. In edit mode, dragging a tag moves its stop (label reads out %); tapping opens the sheet. DECIDED: while the sheet is up the docked tail is a SILENT drag handle — vertical drag moves the stop with no label/% readout (haptic ticks only), the card's ride-up follows live, and taps on it do nothing. (Prototype's tail mode shows a guide line + % bubble; the app deliberately drops that text.) The card travel reuses `Animation.editSlide` (0.22s/0). Ported as `ChooseColorSheet` (native sheet: detent/grabber/glass/swipe from the system) + tap-vs-grab split in `StopTagColumn` + `colorEditShift` in both overlays.
- `bottom-bar.html` — adding and removing colors in stops mode. A glass "+" (bottom trailing, where the gallery's plus lives) adds a color Figma-style: midpoint of the biggest gap, interpolated color, tag slides in from the right and fades in (chosen: 80pt, 330ms, no bounce, landing haptic, no neighbor reaction — the panel still offers the rejected reactions for comparison). Pulling a tag to the right, away from the card, past a threshold detaches it and it flies off the edge, removing the stop. Panel picks a 2/3/6-color example gradient. Ported: `[SkyStop].addingStop()` / `.fading(_:by:)`, `TagPull` + the birth zone in `StopTagColumn` (touch the empty space beside the card → a tag docks at that height; dismiss = the delete pull), `addStop()` in the overlays; the working "+" sits in the gallery plus's spot. `#edit+add2` in the URL deep-links to stops mode with two inserts, for screenshots.
- `gallery-controls.html` — jiggle mode on the gallery grid (the home-screen idiom, in Liquid Glass). Hold a tile or the empty background: every tile starts to wobble (restrained: ~1°, 300ms, each on its own beat), a small glass "−" badge pops onto each, and the bottom-right "+" morphs into a "✓". Tap a badge to delete (tile shrinks away, grid closes up); drag a tile to reorder (others make room). Once anything changed, a glass "↺" appears bottom-left and puts the grid back the way it was; "✓" or a background tap commits and settles. No Done pill, no toast. Panel tunes hold time, wobble presets/angle/period/bob/sway, badge glyph/position/size/pop, the +→✓ morph, when ↺ shows and how much it undoes, delete guard (↺ vs. tap-again red badge), exit style, pick-up lift and reflow springs. A move before the hold lands cancels it (that's the scroll). `#jiggle` in the URL starts awake. Ported: `Jiggle` constants + `Wobble` + `DeleteBadge` in `Components/JiggleMode.swift`, the +→✓ crossfade as `alternateSystemName` on `GlassIconButton`, and the mode itself (working-copy `draft`, ↺ = back to `store.items`, slot-offset drag reorder, `SkyStore.replaceAll` on ✓) in `GalleryView`. `SKY_AUTOPLAY_JIGGLE=1` wakes the grid on launch. DECIDED: the badge is a flat translucent disc (semantic background fill, quaternary rim, tertiary glyph) riding the wobble — not Liquid Glass. Glass that wobbles breathes in size (tried plain, pinned, and in a GlassEffectContainer) and materials make the grid lag; the flat disc holds its size. The wobble is a frame clock (`TimelineView`), not `repeatForever` — a repeating animation leaked rotation onto tiles after exit. Keep backdrop effects and blurred shadows off the idle tiles or the grid lags.
- `color-picker.html` — rethinking the Choose-color sheet. Starts on the blank sky (white → gray), where HSB's hue slider is a DEAD control (saturation 0 → every hue is the same gray). Panel compares: model HSB (Figma's axes) vs. OKLCH (lightness · chroma-as-%-of-sRGB-max · hue, the same space the sky blends in; hue turns without changing lightness); "wake" (the first hue move on a gray lifts saturation/chroma to a tunable amount and pulls pure white/black in, thumbs glide there; the OKLCH hue track previews where you'll land); three sliders vs. a 2D pad + hue; header A (today: 24pt leading title, flat X) / B (iOS 26: small centered title, glass X trailing) / C (X = revert, ✓ = keep) / D (X only) / E (default, the UIColorPickerViewController layout: EYEDROPPER leading, small centered title, glass X trailing), title size. The dropper glyph in the app is the SF Symbol `eyedropper.full`, in the ✕'s exact treatment (19pt black rounded, tertiary) — tried the design's own SVG as a Path (came out lighter than the ✕ in the glass sheet: iOS inks shapes and images differently) and as a template image; the system symbol matches by construction. Tapping it drops the sheet and OUR OWN SKY ZOOMS IN to fill the screen — DECIDED: no photos, the eyedropper picks from the gradient preview itself. A full-screen copy of the card's gradient (drawn row by row in Oklab) starts exactly over the card (clipped to its rect/corner, content squeezed to 370/402 × 548.66/874, ride-up included) and opens to the whole phone; after the pick it zooms back into the card showing the updated sky. It's the hero move, so it reuses those springs: in = `heroOpen` (0.31s, bounce 0.19), out = `heroClose` (0.26s, 0). LAYERS are fixed for every state so nothing pops across anything mid-move: card < zoomed sky + lens < HEADER < sheet — the header rides above the sky so the title holds its place through the whole pass (it used to be covered and reappear late, as if waiting on the sheet); and the card doesn't move while picking (ride-up kept), so the zoom leaves from and lands on the card exactly and no edge slides out from under it. The lens FLIES OUT OF THE PIPETTE BUTTON (its frame comes from the sheet via `onPick(CGRect)`): button-sized (44/120) at the button → full size mid-sky on the zoom's own `heroOpen`, no delay, one motion with the zoom; on pick/cancel it flies back into the button on `heroClose`, fading, carrying the color. NO invented springs, no materialize (tried: read slow, not ours). Glass covers the WHOLE lens (`.glassEffect(.clear, in: .circle)` over the magnified sky) — a rim-only ring was tried and rejected: it changed the look. The loupe is a Liquid Glass lens (for the app: `glassEffect`), not a pixel grid: smooth 3× magnification, bright rim + top-left specular, the sampled point marked by the sheet's own slider thumb (`ColorThumb`, 36pt/3pt ring, filled with the color you'll get) — no invented reticle. DECIDED: the lens JUMPS TO THE FINGER ON TOUCH-DOWN and follows the drag from there (tried relative trackpad-style dragging first; rejected); lift after a drag takes the color under the lens. No explainer text. CANCEL IS THE HEADER'S TRAILING BUTTON: in create, the ✓ swaps to ✕ (`GlassIconButton` alternateSystemName, `glyphMorph`) and the leading ✕ fades out (one ✕ on screen); in detail, a ✕ pops in at that trailing spot and the ‹ fades out. `#pick` opens the sheet, then plays the zoom. DECIDED for the app: HSB stays (Figma cross-check), wake on (to 100% saturation, black to 50% brightness, gray = below 1%), three sliders, header E with a small centered title (22pt BOLD rounded, the app's title weight — semibold read thin; tried 24 and 17). Ported: `wakingHue` + the eyedropper/title/✕ toolbar in `ChooseColorSheet` (flat quaternary buttons, as the ✕ already was), `PipetteGlyph` + `EyedropperSession` + `SkyEyedropper` (zoom layer = the card itself, `GradientCard` with its 55pt shape, hidden between passes, its FRAME animated — tried a render-only scale + separate animatable clip: under a fast trigger the two fell out of step and showed square corners; lens = its own view `EyedropperLens` owning the drag, so a drag re-renders only the lens; the magnified sky is a lens-sized strip of the gradient (3× tall, offset to the sampled point — it only varies vertically), never a full-screen layer scaled + masked + shadowed per frame; gradient built once per pass; `.glassEffect(.clear)` on top) in `Components/Eyedropper.swift`, `[SkyStop].hex(at:)` for the read, and `startPick`/`finishPick` in both overlays. DECIDED (after trying the alternatives): the SHEET DROPS for the pass (swallowed onDismiss so the card stays put) and rises again with the new color — collapsing it to a tiny detent instead was tried and REJECTED: the floating sheet turns into a rectangle as it shrinks. A dropped sheet leaves something behind that eats the NEXT TOUCH (the lens missed the first drag every time, however long you waited), so the lens is driven by a recognizer on the WINDOW (`WindowTouches`: long-press, 0s, simultaneous with everything, never cancelling), not a SwiftUI gesture; touches starting on the header's ✕ are excluded so it cancels; the sky zooms UNDER it to the WHOLE SCREEN, with the GRADIENT scoped to the safe area (full width, top inset → bottom inset) and its first/last colors running on past it to the screen edges — a safe-area-sized rounded sky let a ridden-up card peek out around it; frame, gradient scope and 55pt corner are one layout on one spring, and at full screen the corner hides inside the display's rounding — keeping the sheet up made its glass re-blur the moving sky every frame (laggy) and left the sheet in view; a separate overlay window made the zoom flaky. The docked tag is GONE the instant a pass starts (no fade) and comes back IN STEP WITH the zoom home — as a twin drawn ON TOP of the sky, glued to its trailing edge, fading in on `heroClose`, handed over to the real tag (hidden until then: `EyedropperSession.hidesTag` → `StopTagColumn.hidesDocked`) on the spot where the sky lands. Fading the real tag in beneath the sky made it pop out when the edge passed. The lens is clamped to the zoomed sky and reads location relative to it. A drag's release takes the color under the lens; a quick TAP takes the color right where it landed and goes back too (under 4pt of travel counts as a tap). Closing the gradient dismisses the sheet (and any pass) at once, so it leaves with the card (`isClosing` swallows its onDismiss). Wake defaults as tuned: on, wake to 100%, gray below 1%, no dimming. Deep links: `#oklch+pad+C`, `#nowake`, `#pick`, `#card`, skies `#dusk` `#night` `#black`.
- `app-icon.html` — the app icon: MODERN SKEUOMORPHIC, a thick glass lens set in a panel with the sky behind it. One thing, no card/tags/label, has to survive at 29pt. Canvas-drawn so the 1024 export is exactly the preview; every metric is a share of the icon size, and the board renders the same drawing at all seven iOS sizes (180→29, actual pixels), at 52pt on light and dark home screens, and once per palette. SHAPE: the real Apple squircle — each corner an arc with Bézier segments easing into both edges (Figma's squircle construction), the mask being 22.37% radius at 60% smoothing (`MASK_R`/`APPLE_SMOOTHING`), built as an SVG path string handed to `Path2D` so the arc stays exact. `layout()` derives mask, aperture (concentric with the icon corner, then opened toward a full round by `roundness`) and glass; the glass is offset along the light so one side of the opening is wider — that off-axis view is what makes a recess read as a recess rather than as a drop shadow. WELL is the default look (matte white bezel, dark ceiling, lit sill — the airplane-window read the design landed on). GLASS ( `glassRefraction` + `glassFinish`): across the bezel the sky keeps going but COMPRESSES — `skyGradient(box, pal, squeeze)` runs the same stops through a shorter distance, piling the gradient into a narrow band the way a lens squeezes what is behind it. DECIDED: that bending is a TINT, not a picture — a wash of the panel colour pulls the wall back toward its own white (`bleed`, default 0.26), and the refraction pass runs BEFORE `materialLighting`/`materialGrain` so the wall reads as the panel's own surface under the same light rather than a band pasted on top. The crisp finish (specular, chromatic split) runs after, so grain never softens it. A fully opaque dark refraction was tried first and read heavy; the earlier matte white well looked better, and this keeps that while staying glass. CORNER RULE (`nestedRadius`, slider 'Concentric → proportional', shipped at 1 = proportional): CONCENTRIC means r = R − gap, a constant gap all the way round, which is what an offset curve really does — but each nesting eats a fixed amount, so with the shipped 9.5% panel + 10.5% wall it left the glass at 4% of its own width and the icon read as a rectangle. PROPORTIONAL means r = R × (inner width / outer width), so every shape is a scaled copy of the icon and the 22.37% corner character survives any number of nestings. The two nearly agree for a thin wall and diverge hard for a thick one. ARTIFACT GOTCHAS (two separate causes, both fixed — check these first if stipple reappears): (1) RING SEAMS. Anything built as a stack of thin CLIPPED rings leaves each ring's antialiased edge to meet its neighbour's, and the mismatched coverage reads as a crosshatch moiré along the curve — worst over a flat dark wall. The bezel is therefore painted outer-to-inner as NESTED FILLS (each covers everything inside it, so the next soft edge composites over solid colour) and `well`/`plug` depth is a single `sillOcclusion` pass: the glass shape casts a shadow OUTWARD onto the wall, clipped so only the shadow lands, which hugs the sill and follows the corner exactly. (2) GRAIN RESAMPLING. `textureTile` generates noise at the exact pixel size it will be drawn and caches per (material, size); drawing one 256px tile scaled DOWN resamples high-frequency noise and aliases into the same crosshatch. Scaling a tile UP only blurs, so that direction is allowed and capped at 256.  Step count scales with size (`wallSteps`, 5 at 29px → 30 at 1024). Directional shading is a CONIC gradient (`wallLight`): at perimeter angle φ the inward normal is (−cos φ, −sin φ), so the light caught is cos(φ − θ). Four mitred faces were tried first and read angular and cheap. Panel gives control of everything: refraction, specular, chromatic edge, panel frost (the panel carries the sky behind it), wall thickness, opening roundness, light angle, look off-axis, wall shading, edge highlight, panel width/tint, material (flat/plastic/brushed/paper/leather/glass grain tile composited in `overlay`, sized as a share of the icon so texture vanishes below ~3px like real texture), vignette, gradient angle/zoom, and an Apple template grid over the hero (preview only, never exported). `well`/`plug` swap the lens for a milled recess. DECIDED on frame weight: panel 7% + wall 5.5% put the opening on the grid's first ring and looked right in the 1024 master, but on a real home screen that bezel is only ~4pt wide and the window read vanished — judge frame weight on the 60/80 steps of the ramp, never on the hero. Shipping 9.5% + 10.5%, so the surround is a fifth of the icon on each side. DECIDED: the iOS 6 gloss shine is OFF by default — it fights the material. GOTCHA: shapes are `Path2D` values, never drawn straight onto the context — `innerShadow` composes a rect with the shape as an even-odd hole, and a builder that called `ctx.beginPath()` wiped the rect and filled every swatch solid black. APPEARANCES: the icon ships LIGHT + DARK (`AppIcon.png` / `AppIcon-Dark.png`, the dark one keyed by an `appearances: luminosity/dark` entry in `Contents.json`, both fully opaque). The dark variant is the SAME drawing with the `DARK` override set applied via the `#dark` deep link — panel goes near-black, edge highlight up to 0.75 so the icon keeps a silhouette on a dark wallpaper, vignette down to 0.12 because darkening an already-dark panel only turns it to mud. Keeping it as overrides rather than a second file means the two appearances cannot drift. No tinted variant yet; the system derives one. THE PROTOTYPE IS THE ICON'S SOURCE OF TRUTH: its panel defaults are the shipped design, and `scripts/icon.sh` regenerates both masters in `Sky/Assets.xcassets/AppIcon.appiconset/` from them — it serves `prototypes/`, loads `app-icon.html?png=1` (which swaps the page for the 1024 master's base64), decodes it with headless Chrome's `--dump-dom`, and checks the PNG header really says 1024x1024. `scripts/icon.sh ember` picks a different palette. Anything tuned in the browser only ships once those defaults are edited into the file and the script is re-run; the "Download 1024 PNG" button does the same thing by hand. Shipped values: night palette, plastic, grain 0, light shaping 1.2, canvas panel at 9.5%, well, wall 10.5%, refraction 0.92, sky-in-wall 0.5, specular 1, chroma 0.12, frost 0, light 90°, off-axis 0.18, wall shading 0.85, edge 0.45, vignette 0.4, gloss 0. Deep links combine with `+`: `#leather+plug+dusk`, `#well+ember`, `#bleed`, `#grid`.
